# 园区三类有向依赖网络

当前模拟数据版本为 `park-v3`，36个业务主体、101条有效关系。数据角色、月度台账、迁移备份及A案例结果详见[园区业务数据重构结果](PARK_DATA_RECONSTRUCTION.md)。

依据策划书的采购/销售、能源、公共设施三类依赖及两阶传播设计实现。存储与计算中的 source → target 为“风险影响方 → 依赖方”；业务依赖视图反向呈现“依赖方 → 被依赖方”。两者都不表示货物流或付款方向。

## 关系分类与展示

| 类别 | 方向示例 | 图示 |
| --- | --- | --- |
| 采购/销售依赖 `supply` | 供应商 → 采购企业；客户 → 依赖其销售的企业 | 蓝色实线箭头 |
| 能源依赖 `energy` | 能源供应方 → 用能企业 | 紫色虚线箭头 |
| 公共设施依赖 `infra` | 公共设施服务方 → 使用企业 | 灰绿色点线箭头 |

银行端将原“园区综合风险”和“压力测试”合并为“园区风险分析”。页面只保留一个分析情景选择器和两个视图，不提供手动缩放。

- 业务依赖关系：默认当前企业两阶依赖，中心为目标、一阶内圈、二阶外圈，保留园区总览入口；箭头依赖方 → 被依赖方。由风险关系的 target/source 派生 dependent_id/provider_id，原始端点与矩阵保持不变。点击企业切换分析对象；保留节点平滑移动，移出节点淡出，新增节点淡入；点击连线查看详情。同类外围企业默认分组，当前企业与关键服务独立保留；点击分组可展开。
- 风险传导：一张图同时展示传入和传出两阶路径，默认精简为主要传入与传出链路，同侧同层的同类企业可折叠，保留“全部链路”恢复完整图。风险来源在左，当前企业居中，受影响主体在右；同时属于两侧的节点只绘制一次并标为双向关联。全部、一阶、二阶筛选同时作用于两侧，分类筛选保留完整路径。局部与风险图按筛选后的完整链动态排布，节点位置、淡入淡出及画布高度平滑过渡；切换压力情景时主要恶化及风险等级升级主体自动单列，位置与颜色平滑更新。园区总览保持六类业务分区位置。

节点颜色表示所选情景下的风险。压力情景自动与同一数据版本的正常情景对比，显示当前企业和主要变化主体的风险增量；风险视图突出一阶贡献变化幅度最大的三条连线，线宽始终表示依赖强度。节点形状为企业圆形、供能主体方形、公共设施菱形。边详情同时给出依赖方向、风险方向、原始来源与核验状态。

风险视图下方展示自身风险＋一阶净影响＋二阶净影响＝综合风险、主要传入影响、主要受影响主体和对外授信覆盖。综合风险仅由传入分量构成，传出贡献不再加到当前企业风险上。风险来源与受影响主体列表跟随图谱的类型和层级筛选，汇总的是后端已计算路径贡献；当前企业综合风险保留完整口径。详情窗显示正常与压力情景的风险分量、传播贡献及变化；不在主页面恢复矩阵公式或底部说明段落。

## 压力比较与贡献归因

后端使用当前情景和正常情景各自的 r0，按同一个归一化 W 计算一次两阶传播。不得把已经传播的 r* 当作新的 r0 再传播。`network_graph.nodes` 返回 baseline_risk、risk_delta、正常/当前四个风险分量及融资结果；原始关系不随图谱视图反转。

`network_analysis.incoming_paths` 列出所有传入路径，`outgoing_paths` 仅列以当前分析企业为源的传出路径。每条路径分别计算风险传入和显式缓释，净影响为两者之差；正常和压力情景各自计算后再比较，负值不取绝对值参与加法。`recipients` 按接收主体合并本企业的传出贡献，同时单独返回接收主体总风险变化。全园区同时受外部冲击时，两者通常不同，不能将接收方全部风险增量归因于当前企业。

贡献使用截断前分量，与既有矩阵分解一致；综合风险才做 clip。API 中保留该计算口径，路径详情窗说明这一点。公共支持节点不虚构授信；对外授信仍按有效有向关系向外两阶去重，不因同一拓扑下的风险值变化而变化。企业端响应移除 graph、network_analysis、路径及覆盖授信，新增比较数据仅银行可见。

## 原始字段与核验

关系沿用 `source`、`target`、`weight`、`relation_type`，可补充 `relation_id`、`dependency_class`、`direction_basis`、`data_source`、`reporting_period`、`evidence_status`。依赖强度 `weight` 须为 0–1 的有限数，真实业务应以采购/销售占比、能源或设施依赖比例及其证据核验。

既有“供应依赖”归为采购依赖，“客户依赖”归为销售依赖，“公共工程依赖”归为公共设施依赖，保留原端点方向。既有“共享能源”“物流依赖”不足以确认有向供需或公共设施关系，保留待核验，不直接参与风险和敞口；补齐明确的 `dependency_class` 和非空 `direction_basis` 后才可分类。未知端点、非法权重、自环等也保留原因并停用。无类型的三列边仅为旧算法客户端保留“业务依赖”兼容，不作为真实业务数据标准。

原始生成脚本只给出端点、强度和标签，没有供需角色或合同证据。既有可分类关系仍用于演示计算，但详情明确标记“演示方向，业务角色待核验”；不能据此断言某家水泥企业就是实际供能主体或设施运营者。采购详情明确为目标企业从源企业采购，销售详情明确为目标企业向源客户销售。将来须以双方身份、采购/销售记录、供能合同或设施服务协议核验方向，不按名称推测或批量反转。

旧版69条记录中曾有53条有效、16条待核验，已随历史版本备份。当前重构模拟库为采购/销售39条、能源37条、公共设施25条；每条有明确业务角色、商品服务及份额口径，仍标记为模拟未核验。A的向外两阶有效融资客户覆盖为24,681万元、11家，运行模板主体不虚构授信。

实际能源与公共设施节点可由可选 `data/support_nodes.csv` 提供，必需字段：

| 字段 | 含义 |
| --- | --- |
| `node_id` / `node_name` | 唯一编号和名称，不与企业编号重叠 |
| `node_type` | `energy` 或 `infra` |
| `initial_risk` | 有依据的 0–1 运行风险值 |
| `risk_source` | 风险数据来源 |
| `reporting_period` | `YYYY-MM` 报告期 |

当前库的能源站、水务及固废服务主体均为明确标记的模拟业务角色，不声称已获得真实企业或合同资料。支持节点可以传播风险、作为两阶路径的中间节点；不自动赋予企业授信额度，也不计入覆盖企业数。本次未增加银行数据上传入口或改变企业业务数据接口权限。

## 计算口径

三个原始矩阵按 `[目标节点, 源节点]` 写入依赖权重，同端点多渠道相加：

```text
M = edge_scale × (α W_supply + β W_energy + γ W_infra)
W[i,j] = M[i,j] / max(1, sum_j M[i,j])
r* = clip(r0 + λ W r0 + λ² W² r0, 0, 1)
```

当前演示配置 `α = β = γ = 1`，`edge_scale = 0.35`，`λ = 0.55`。类别系数尚未通过历史数据校准，不能解释为已验证的行业权重。类别系数为零的关系不参与风险、路径或覆盖授信。

路径解释使用与传播完全相同的有效权重，多渠道先按端点合并后计算路径贡献；两阶反馈环与矩阵计算一致。TOP3 仅列最大的三条，不代表全部传播贡献之和。

受影响授信沿有效箭头正向遍历最多两阶，企业按最短路径分层并去重，包含当前企业自身；汇总基础授信额度。它表示潜在关联覆盖范围，不是预期损失或按传播概率折算的损失金额。

## 验证

网络单元测试覆盖三层叠加、平行渠道、行归一化、路径贡献与矩阵一致、两阶反馈、模糊关系隔离、支持节点证据校验与授信去重、类别权重关闭；接口测试检查全园区节点、三类关系、待核验记录和覆盖授信。

## 园区缓释与策划书A模拟案例

综合风险保留 `clip(自身风险 + 一阶净影响 + 二阶净影响, 0, 1)`。依赖权重 W 始终非负，不将缓释直接写成负权重，避免二阶负负相乘产生错误增幅。新增参数表 `data/network_mitigation.csv` 独立描述覆盖率、有效性、可用性、压力敏感度、机制及来源；均明确为未核验的竞赛模拟参数。没有参数的关系不推定有缓释。

令有效保障系数 `c = coverage × effectiveness × availability × (1 − shock / reference_change × sensitivity)`（截断到0–1，旧参数默认reference_change=1），`P[target,source]` 为对应有效依赖权重乘 c 的汇总。自身风险用 `1 − P_target`；独立于预测的直接冲击才另行叠加。

- 一阶风险传入为 `λW r0`，一阶缓释为 `λP 1`。
- 二阶风险传入为 `λ²W² r0`，二阶缓释为 `λ²P² 1`；两段均有保障参数才有二阶缓释，任一段缺失时该路径缓释为0。
- 一、二阶净影响分别为风险传入减缓释。API路径和连线同时返回 gross、mitigation、net，所有路径净影响合计与风险分解一致；最终综合风险才截断到0–1。
- 对关系分类筛选保留整条路径，列表按净影响绝对值排序，绿色负值为缓释，红色正值为风险增加；依赖方向与三种线型不变。

`data/reference_case_a.json` 固定A的模拟输入与缓释校准参数，不直接覆盖预测或网络输出。正常情景模型输出约82.6%，数据质量95%，自身风险约17.4%，一阶约−1.70个百分点、二阶约+0.31个百分点，综合风险16%；天然气上涨30%后模型输出约74.0%，一、二阶转为正值，综合风险31%。A的冲击已进入达标概率，额外直接冲击敏感度为0，避免重复计入；其他企业沿用原直接冲击参数。假设情景不改变已报数据质量。

A案例按策划书展示精度将融资支持及网络扣减先四舍五入到万元，再算额度，得到正常628−116＋3000＝3512万元，压力562−221＋3000＝3341万元。A专用模拟定价输入同时校准正常利率3.70%、RAROC9.1%，压力情景继续执行8.5%门槛并转关注；所有值仍由融资函数计算，其他企业沿用原定价参数。减排诊断继续使用原始能源记录，不由风险模块覆盖。

当前数据由 `scripts/rebuild_park_data.py` 可复现生成，只有显式 `--apply` 执行版本迁移，保留历史版本、审核材料及旧参考数据快照。早期A单案例重设工具保留用于旧库兼容，当前完整业务重构使用新迁移脚本。
