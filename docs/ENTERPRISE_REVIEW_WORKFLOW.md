# 企业接入与银行核验闭环

实现日期：2026-10-23。本地模拟业务环境，尚未连接真实企业 EMS、ERP 或银行生产系统。

## 账号与访问

- 银行：`bank_demo`；企业 A：`company_demo` 或 `company_A`；企业 F：`company_F`。其他演示企业使用 `company_<企业编号>`。
- 默认密码 `demo123`，可通过启动后端前设置 `PLATFORM_DEMO_PASSWORD` 改写。
- `POST /api/v1/auth/login` 接收 `account`、`password`、`role`（银行端/企业端），返回 8 小时有效的随机 Bearer token。后端从账号确定企业与角色，不接受客户端自行声明的数据权限。令牌仅散列存入数据库，前端内存保存，刷新需重新登录。
- 企业只能查看本企业分析和材料，不能查看银行园区授信明细、执行银行审核或导入其他企业数据。银行账号不能提交企业数据或证明材料。退出登录撤销当前会话。

## 数据库与初始化

`data/runtime/platform.db` 是工作台业务数据源。首次启动，将已有 36 家企业的 CSV 演示快照及模型训练/关系参考数据迁入新增业务表；后续主工作台从数据库读取。独立算法测试仍可直接读取 CSV。

- `company_versions` / `company_heads`：不可变企业快照与当前生效版本。
- `business_reference`：初始银行授信、关系网络、训练样本等参考数据。
- `review_tasks`：企业、报告期间、数据版本、异常类别、状态与乐观锁修订号。
- `evidence_submissions` / `evidence_materials`：提交说明、拟更正内容、附件字节、SHA-256 与元信息。
- `review_events`：提交与审核意见、处理人、时间及正常情景下的处理前后指标。
- 旧 `datasets`、`workflows` 历史表保留，不影响此次迁移。业务材料、版本及核验记录不会套用旧工作流的最近 100 条清理机制。
- 测试使用独立临时数据库，不写入运行数据库。

## 企业结构化接入

`GET /api/v1/enterprise/data-status`：本企业当前版本、报告期间、来源、项目/资金指标与最新能耗记录。

`POST /api/v1/enterprise/data-sync` 示例（企业 A，能源种类需与当前快照一致）：

```json
{
  "request_id": "ems-A-2026-01-001",
  "source_system": "企业授权 EMS 接口",
  "reporting_period": "2026-01",
  "features": {
    "project_progress": 0.86,
    "milestone_delay_days": 3,
    "fund_usage_match": 0.96,
    "own_fund_arrival": 0.91,
    "cashflow_coverage": 1.72,
    "energy_cost_ratio": 0.28,
    "data_completeness": 0.97
  },
  "energy_records": [
    {"energy_type":"coal","energy":31,"output":106,"emission_factor":2.5},
    {"energy_type":"gas","energy":16,"output":106,"emission_factor":2.0},
    {"energy_type":"electricity","energy":26,"output":106,"emission_factor":0.55}
  ]
}
```

请求头为 `Authorization: Bearer <企业会话令牌>`，企业身份由后端绑定，无需提交 company_id。企业不能修改银行基础授信、身份或关系边。

- 同一企业、同一 request_id、相同内容重复发送返回原接收结果，不重复入库；同编号内容不同返回 409。
- 新请求只能新增已发生的新报告期，需完整提交该期能源种类、统一产量和正数能耗/排放因子。已入库期间的修订通过补充材料提出，审核后生成新版本，防止通过接口覆盖待核验数据。
- 核算碳强度、改善趋势与能效/能源结构贡献特征，再重新执行预测和融资链。新版本使旧版本未结任务转为“历史版本”，历史材料和结论保留。
- 企业端提供明确标为“本地演示”的常规与检修期请求生成器。它通过同一个接口入库，不冒充已接通外部系统。

## 异常与补充材料

以下为本原型演示核验阈值，不代表银行正式阈值：组合异常分数 ≥0.4；资金用途一致率 <0.9；里程碑延期 >15 天；相邻报告期单位产量排放变化绝对值 ≥15%。任务基于实际数据，假设性压力情景不生成任务。

- `GET /api/v1/review-tasks`：银行查看全部，企业仅查看本企业；`GET /review-tasks/{id}` 返回对应提交、附件元信息与审核历史。
- `POST /enterprise/evidence`：multipart，字段为 `task_id`（主动补充可空）、`revision`、`version_id`、`explanation`、`corrections`（JSON 对象）、最多 3 个 `files`。
- 文件支持 PDF、PNG、JPG、UTF-8 TXT，内容与类型需匹配，单份 ≤10 MB。文件以随机编号存入数据库；企业上传的名称仅用于展示，不构造磁盘路径。
- `GET /materials/{id}` 授权预览或下载；企业不能访问其他企业材料。前端通过鉴权请求获取 Blob 预览，TXT 按文本渲染，材料不发送外部服务。
- `corrections` 可为 `{"features":{"fund_usage_match":0.96}}` 或 `{"energy_records":[完整本期能耗记录]}`。提出更正时不改变生效数据，审核更正通过才入库。

## 银行审核

`POST /review-tasks/{id}/decision`：JSON `revision`、`action`、至少 5 字符的 `comment`。

| action | 处理 |
| --- | --- |
| approve_reasonable | 有佐证材料后标记已核验合理，关闭该事项，保留原始数据 |
| approve_correction | 必须有材料与更正内容，生成新企业版本、重新识别任务并重算 |
| return | 退回补充，企业可再次提交，旧提交仍保留 |
| track | 确认仍需关注，继续跟踪，允许后续补证 |

只有当前生效版本的待审核任务可处理；重复审核、过期修订号或旧版本材料返回 409。写操作使用 SQLite 事务和修订号校验。

“数据组合异常”核验合理时，仅解除该版本正常情景下的组合异常质量惩罚：`Q_effective = clip(data_completeness, 0.55, 1)`。原始异常分数和原始质量值保留，融资规则使用核验后的有效异常标记。能耗、延期、资金事项结案只改变事项处置状态，不清除实际风险；压力情景和新数据版本不继承该豁免。

转型可信指数继续按 `100 × P_target × Q_effective` 计算。审核不直接设定概率、指数或融资额度，也不自动修改正式合同。界面显示原始异常分数、当前核验状态及审核前后指数/质量/版本变化。

## 本地演示

1. 用企业 A 登录，打开“数据接入与补充材料”，展开本地接口演示，选择检修期场景，生成并发送请求。
2. 在新生成的能耗波动或组合异常任务中填说明，选择证明附件并提交。
3. 退出后用银行账号登录，打开“审核任务清单”，查看企业材料与历史，在审核抽屉中记录核验意见。
4. 合理结案或更正通过后查看处理前后对比。返回企业端可看到结论与记录。

后续真实对接需使用企业授权系统凭证与正式身份服务替代本地演示账号，明确数据更新周期、完整度计算责任与正式审核权限。本轮未接入外部企业或银行系统。

## 四因素减排归因的工艺数据

银行端页面名称改为“转型可信度评价”，正文顺序为减排归因分析、未来12个月的转型达标概率；预测区仅显示概率，原四维依据区已移除。

企业接口增加可选 `route_records`，与 `energy_records` 一起提交新报告期的工艺路线明细；`GET /enterprise/data-status` 返回已接收的历史明细。银行不能导入。每期所有路线必须完整提交，不能只提交改变的某一条路线。单条格式如下，数值为与前述接口例子匹配的说明示例：

```json
{
  "period": "2026-01",
  "route_id": "route-1",
  "output": 106,
  "process_emissions": 12.6,
  "energy_records": [
    {"energy_type":"coal","energy":31,"emission_factor":2.5},
    {"energy_type":"gas","energy":16,"emission_factor":2.0},
    {"energy_type":"electricity","energy":26,"emission_factor":0.55}
  ]
}
```

- 路线产量合计、逐能源能耗合计和排放因子须与同期总记录一致；每期路线编号唯一。零产量路线只接受零能耗、零过程排放。
- `process_emissions` 是非燃烧过程排放，不能再次包含已计入能源部分的排放。各能源须先转换为一致的能量单位，因子相应换算；过程排放与能源排放须采用相同的排放单位、期间和边界。历史演示数据未声明物理单位，因此界面只显示原始核算单位。
- 新接口只接受当前新增报告期的明细。补充历史基期或更正已入库明细，通过企业证明窗口的“工艺路线明细（含历史补充）”提交 `corrections: {"route_records": [...]}`，附证明后由银行“更正通过”生成新版本。企业可在同一申请中提交基期、报告期的完整明细；未通过前不改变归因。
- 已有工艺明细时，能耗更正也必须同步提交与更正总量一致的工艺明细；否则拒绝，避免数据库出现不一致的两套事实。
- 基期与报告期均有完整工艺明细时，使用下式扩展 LMDI（r 为路线，j 为能源）：

```text
C = Σ(r,j) Q × s_r × I_r × m_rj × F_j + Σ(r) Q × s_r × P_r
```

Q 是总产量，s 是路线产量占比，I 是路线内单位产量能耗，m 是路线内能源结构，P 是单位产量非燃烧过程排放。Q 变化归入产量、I 变化归入能效、m×F 变化归入能源结构、s 与 P 变化归入工艺；新增或退出的路线采用正数极限，不虚构路线内能效变化。

缺失任一比较期工艺明细时，只分解能源部分，`lmdi.process=null`、`process_available=false`，不以零或残差填补。完整时 `process_available=true`，四项合计与能源加已纳入工艺排放的差额对齐；后端校验残差容差。

`lmdi.conclusion` 仅返回一句最终分析，不重复数值。主要减排来源只比较负向效应，按页面百分比的两位小数识别并列；后半句依据产量增长/稳定/收缩和排放下降/持平/上升生成。缺少工艺时，结论明确限定能源核算范围。预测模型仍使用已有十项训练特征；新增工艺归因不直接改造已有模型概率或另加人工权重。

### 归因百分比展示

`lmdi.effect_percentages` 返回四项效应各自除以同一基期排放量、乘以 100 后的结果；`total_change_percentage` 是排放净变化除以基期排放量乘以 100；`percentage_basis=base_emissions` 标识分母。字段值 -20 表示 -20%，不是 -0.2。工艺缺失时仍为 null。原始量值保留，供核算和兼容旧接口。

这些百分数表示相对基期排放的影响，不是各因素占全部减排量的构成比，不能改为合计 100%。按原值计算后，各因素百分数之和等于净变化百分数；显示两位小数可能有尾差。界面移除基期、报告期排放量，只保留净变化百分比和四因素图。未来12个月的转型达标概率与标题同排显示。

### 工艺原始数据与 SHAP 展示

2026-10-23 核查：运行库当前 36 家演示企业均无 routes；原始 CSV、20 条历史导入、15 条历史工作流和已有补充材料均没有企业工艺明细。业务需求及策划书给出了工艺字段要求，但没有可入库的路线产量、过程排放数值。按用户选择，仅使用可核验企业原始数据，保留工艺缺失标记；不采用行业平均数、项目预期减排量或分解残差冒充企业过程实测值。

概率区下方列出当前企业/情景的 SHAP TOP5 因素名称、策划书输入类别和方向，不展示原始 log-odds 数值，也不把它们当作概率百分点。方向相对模型基准，不是因果判断。当前模型实际使用十项输入，未训练的投资总额、工艺指标或外部行业指标不作为 SHAP 因素虚构列出；压力情景的模型输入变化可以解释，模型之外的额外概率调整单独注明。

### SHAP 概率贡献量化

新增 `shap_probability`：方法 `interventional_probability_shap`，单位 `percentage_points`。背景为训练分割内固定随机抽取的 100 条样本，不使用当前企业或测试集作为背景。通过 SHAP TreeExplainer 的 probability 输出直接分解 LightGBM 概率（[官方说明](https://shap.readthedocs.io/en/latest/generated/shap.TreeExplainer.html)），保留旧 raw SHAP 字段兼容既有接口。

- `items`：全部十项按贡献绝对值排序，`contribution` 为概率差值，`contribution_pp=contribution×100` 为百分点。
- `base_probability`、`model_probability`、`total_contribution_pp`：验证 基准概率＋因素合计/100＝模型概率，容差 1e-6。
- `scenario_adjustment_pp`、`final_probability`：验证 模型概率＋情景调整/100＝最终概率。情景规则中的额外惩罚与上下界截断都归入该调整，不伪装为特征 SHAP。
- 页面默认关键五项，可展开全部十项；折叠时显示其余五项合计。条形以零为中心、共用全体因素的最大绝对值刻度。
- +5 个百分点表示对概率分配 +0.05，不是相对增长 5%。基准与贡献的加法核对在后端保留，页面不单独展示基准数值或重构公式；SHAP 不代表修改单一输入的因果效果。

页面精简：SHAP 列表标题为“关键因素及其贡献”；因素名称下的分类小字已移除，只保留名称、贡献条形及百分点数值。基准概率仍用于计算，业务界面不展示其数值和重构公式；压力情景的额外调整保留独立说明。
