# 工银“碳跃智衡”

面向高碳产业园区的可信转型融资与动态风险管理平台。项目将企业转型数据转化为银行可解释、可追溯的辅助决策信号，形成“真实转型识别 -> 园区关联风险 -> 动态融资决策”的完整计算链。

> 本仓库是竞赛算法原型，全部企业、交易、授信和模型数据均为模拟数据；支持比例、网络参数、RAROC 阈值等均为演示参数。输出仅为辅助决策建议，不代表工商银行真实客户、内部模型、正式授信结论或合同调整。

## 1. MVP 目标

原型围绕三分钟路演主线实现：

1. 企业申请转型项目融资，展示基础授信和项目资金需求。
2. LMDI 分解排放变化，识别减排来自产量、能效还是能源结构。
3. LightGBM 预测未来 12 个月转型目标达标概率，SHAP 输出关键驱动因素。
4. Isolation Forest 识别能耗、项目进度和资金使用的异常组合，只触发人工核验提示。
5. 加权有向网络计算自身、一阶和二阶关联风险，并给出主要传播路径。
6. 在气价、电价、煤价、碳价和核心客户需求压力间切换，联动更新达标概率、网络风险、额度、利率、RAROC 和贷后建议。

## 2. 功能范围

## 3. 算法链

### 3.1 LMDI 真实减排识别

按企业基期与最新报告期，在相同核算范围内分解排放变化：

```text
Delta C = Delta C_activity + Delta C_efficiency + Delta C_energy_structure + Delta C_process
```

没有工艺明细时，核算范围仅为能源相关排放，工艺效应返回 null，页面显示“待补充”。企业补充可与总量核对的分路线产量、能耗和非燃烧过程排放后，扩展为四因素 LMDI：路线内能耗强度变化计入能效；路线占比和非燃烧过程强度变化计入工艺，避免重复计算。能源结构包括能源占比及对应排放因子的变化。四项之和必须与覆盖范围内排放净变化对齐，差额不能冒充工艺效应。

页面仅展示四项效应的百分比瀑布图，不展示基期与报告期排放量。净变化及各项效应均以基期排放量为分母换算为百分比，负值表示减排、正值表示增排，各项相加等于净变化（显示值可能有四舍五入尾差）。图下突出展示一句按实际结果生成的结论；减排贡献最大项按百分比两位小数并列时，同时列出。企业接口与历史明细审核见 [企业接入与银行核验闭环](docs/ENTERPRISE_REVIEW_WORKFLOW.md)。

### 3.2 转型目标达标概率与解释

LightGBM 基于模拟企业样本训练二分类模型：

```text
P_target = P(未来 12 个月按计划完成转型目标 | X)
```

特征覆盖真实减排、项目执行、资金行为、经营承受力和数据可信度。SHAP `TreeExplainer` 输出单企业 TOP5 正负驱动因素。比赛数据使用固定随机种子生成，并保留独立测试集指标，结果不宣称代表真实业务准确率。

顶部首位展示“减排归因评价”，取归因分析的同一组减排因素，生成“能效改善主导”“能源结构主导”“产量收缩主导”“多因素共同驱动”等简短文字；排放上升时显示“减排尚未抵消增排”或“排放仍在上升”。不将贡献因素解释为信用评级，不显示指数、分数或分母。点击卡片入口定位到完整减排归因分析。原 `transition_credibility` 与 `transition_score` 后端字段保留兼容，融资及风险计算不受文字展示替换影响。

银行端“转型可信度评价”、企业端“转型可信度”正文均只保留两个板块，顺序为“减排归因分析”→“未来12个月的转型达标概率”。预测板块标题与概率百分比同排，下方按概率口径 SHAP 列出贡献绝对值最大的五个实际输入因素、带符号的百分点贡献和同刻度条形，可展开全部十项，标题为“关键因素及其贡献”。页面不显示因素分类副标题、基准概率数值或概率重构公式，计算与核对仍保留在后端。顶部摘要使用与正文同源的归因评价文字。概率 SHAP 使用固定抽取的 100 条训练子集样本作为背景，采用 interventional TreeExplainer(model_output="probability")。基准概率加全部因素贡献须与模型概率对齐；压力情景额外调整独立列出，并与最终概率对齐。旧 shap 字段仍保留原始 log-odds TOP5，新增 shap_probability 字段提供十项概率贡献，不直接把原始 SHAP 乘100当作概率百分点。当前模拟训练模型的输入仍为现有十项特征，没有将新工艺效应伪装为已训练特征。

### 3.3 异常检测与数据可信度

Isolation Forest 对能耗、产量、项目进度和付款等特征做无监督异常检测：

```text
Anomaly Score increases -> Q_data decreases -> transition support decreases
```

异常分数只用于降低数据可信度或触发人工复核，不直接认定企业漂绿或造假。

### 3.4 园区两阶风险传播

园区网络分为采购/销售依赖、能源依赖、公共设施依赖三层。边 `source -> target` 表示风险影响方指向依赖方：供应商指向采购企业，客户指向依赖其销售的企业。实际能源或公共设施节点须提供风险值、来源和报告期，不自动生成。

```text
r0_i = a * (1 - P_target_i) + b * ShockSensitivity_i
W_raw = alpha * W_supply + beta * W_energy + gamma * W_infra
W = 按目标节点对 W_raw * edge_scale 做行归一化（行和最多为 1）
P = 有效依赖权重 × 独立缓释系数（无来源参数为0）
first_net = lambda * W*r0 - lambda * P*1
second_net = lambda^2 * W^2*r0 - lambda^2 * P^2*1
r* = clip(r0 + first_net + second_net, 0, 1)
```

“园区风险分析”合并原压力测试入口，提供业务依赖关系、风险传导两个视图。业务箭头依赖方 → 被依赖方，风险箭头影响方 → 受影响方；只反转业务视图呈现，原始关系与风险矩阵不变。风险图在同一画布左侧显示风险来源、中央当前企业、右侧受影响主体；双向关联主体去重，全部/一阶/二阶筛选同时作用于两侧。

单一情景选择器复用现有价格和需求冲击，压力下自动对比正常情景，节点显示风险和主要增量，企业局部与风险图切换依赖类型或层级时按可见链路动态重排，节点移动、淡入淡出及画布高度同步过渡，园区总览保留六类业务分区。详情窗分解自身/一阶净影响/二阶净影响/综合风险，并区分接收主体总风险变化与当前企业的传出贡献。后端按同一 W 对两套 r0 分别计算，不重复传播已经汇总的综合风险。传出贡献不加入当前企业综合风险，主要路径贡献口径为截断前分量。原有待核验关系仍保留，企业端不会获得园区图谱及归因数据。前端有向路径与布局可用 `npm run test:graph` 验证。 业务图默认精简同类外围企业，可点击分组展开或恢复全部主体；风险图默认选择主要传入、传出链路并缩短高度，可切换全部链路。图形合并仅用于展示，保留逐企业风险与授信计算及原始连线明细。压力情景按相对正常情景的风险增幅列出前三个主要恶化主体；主要恶化与风险等级升级主体自动单列并加红圈。

受影响授信敞口以当前企业为起点，沿有效有向关系查找一阶、二阶可达企业，并包含当前企业自身。按企业去重汇总 `base_limit`（基础授信额度，单位万元），重复路径只计一次，传播层级按最短路径归类；公共支持节点可作为中间节点，不计入企业数和授信。页面可展开查看各层敞口和企业明细。当前关系结构及基础授信额度不随压力情景变化，覆盖范围和敞口金额保持对应关系结构的统计口径，风险值随情景重新计算。

当前 `park-v3` 模拟库为36个具备业务角色的主体、101条关系：采购/销售39、能源37、公共设施25。19家生产主体适用转型模型，17家供应、客户、供能及设施主体使用运行画像，不生成未适配的转型概率或融资建议。A的向外两阶有效授信覆盖24,681万元、11家。旧数据及审核记录保留于版本和备份；详见[园区业务数据重构结果](docs/PARK_DATA_RECONSTRUCTION.md)及[有向依赖网络设计](docs/DIRECTED_DEPENDENCY_NETWORK.md)。

### 3.5 动态融资与 RAROC

```text
L_transition = C_project * alpha * P_target * Q_data
L_network = (L_base + L_transition) * min(g_max, k * R_network)
L_final = L_base + L_transition - L_network

R_loan = R_base + RP_credit + RP_network - D_transition
RAROC = (loan_income - expected_loss - operating_cost) / risk_capital
```

融资决策页面展示初始测算 RAROC、8.5% 演示门槛及百分点差额，并按高于、低于或刚好达到门槛输出对应说明。若初始建议利率下的 RAROC 低于阈值，系统调整建议利率并独立展示定价校验后的结果，同时保留初始测算值及贷款收益、预期损失、运营成本和风险资本明细。

## 5. 运行

启动命令优先使用项目 `.venv` 中的 Python，也可通过 `PYTHON` 环境变量指定解释器；没有 `.venv` 时使用 PATH 中的 Python。推荐使用 Python 3.12。

macOS / Linux 首次安装：

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.txt
npm ci
npm run dev
```

macOS 的 LightGBM 还需要 OpenMP 运行库，使用 Homebrew 时可执行 `brew install libomp`。当前工作区的部署信息见 [本地部署说明](docs/LOCAL_DEPLOYMENT.md)。仓库已包含模拟数据，仅在需要重新生成时运行 `node scripts/python.cjs scripts/generate_demo_data.py`。

也支持 Conda 环境（已有 `.venv` 时，可设置 `PYTHON` 指向 Conda 解释器）。首次安装：

```powershell
conda activate pytorch_env
pip install -r requirements.txt
python scripts/generate_demo_data.py
npm run install:all
```

一条命令启动 FastAPI 与 Vue：

```powershell
npm run dev
```

根目录 npm 脚本通过 `scripts/python.cjs` 启动 Python，优先使用项目 `.venv`。原 Windows Conda 启动脚本 `scripts/run_python_task.ps1` 也已保留，可在对应环境中单独使用。

Vite 前端支持热更新；后端为保证 Windows 与模型运行稳定采用普通 Uvicorn 进程，修改 Python 后重新执行 `npm run dev`。

- Vue 前端：<http://127.0.0.1:5173>
- FastAPI 文档：<http://127.0.0.1:8000/docs>
- 健康检查：<http://127.0.0.1:8000/health>

也可以分别运行：

```powershell
npm run dev:backend
npm run dev:frontend
```

运行后端测试与前端生产构建：

```powershell
npm test
npm run build
```

## 6. 验收标准

- `pytest -q` 全部通过。
- 固定随机种子下可重复生成模拟数据并训练模型。
- Vue 页面可切换企业端/银行端、企业和正常/压力情景，无异常堆栈。
- FastAPI 的健康、兼容的园区汇总和企业分析接口返回有效 JSON。
- LMDI 各效应之和与总排放变化在容差内一致。

- 压力场景能联动改变达标概率、网络风险和融资建议。
- 所有关键结果标注“模拟演示/辅助决策”，不出现自动批贷或直接认定漂绿的表述。

```text
POST /api/v1/auth/login                    登录，返回 Bearer 会话
POST /api/v1/auth/logout                   撤销当前会话
GET  /api/v1/enterprise/data-status         本企业当前数据状态
POST /api/v1/enterprise/data-sync           企业结构化接口接入
POST /api/v1/enterprise/evidence            企业说明、佐证及拟更正数据

POST /api/v1/review-tasks/{id}/decision     银行核验与重算
GET  /api/v1/materials/{id}                 鉴权预览证明材料
```

证明材料支持 PDF、PNG、JPG、UTF-8 TXT，最多 3 份、每份 10 MB。合理波动结案保留实际数据；更正通过形成新版本并重算。组合异常核验只解除当前版本正常情景下的对应质量惩罚，原始分数、真实经营风险与压力情景继续保留。

详细接口结构、核验状态、数据表和演示步骤见 [企业接入与银行核验闭环](docs/ENTERPRISE_REVIEW_WORKFLOW.md)。

原有多 Agent 独立页面保持移除，银行会话仍可查看已有工作流历史及使用已有数据集执行工作流。旧文件导入入口对银行返回 403，对企业返回 410 并指向新接口。离线数据验证及 LangGraph 工具保留用于测试和历史兼容；在线 DeepAgents 仍需自行配置模型与密钥。

## 8. 后续落地边界

真实落地需要完成企业授权、数据分级分类、接口审计、行业口径治理，并使用真实历史转型项目进行分行业训练、概率校准、时间滚动验证和模型风险审批。钢铁模型不能直接套用于化工等异质行业；银行现有基础授信与人工审批始终保留最终决策权。

银行端默认进入转型可信度评价，已移除园区驾驶舱页面与导航，前端不再请求其汇总数据。侧栏工作台名称和工作区页面标题上方不再显示英文副标题；审核任务清单的页头不显示当前企业、行业或情景信息。
